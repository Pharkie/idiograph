# Idiograph's checks

## What to run

In a build, check the areas your change touches, once, at the end, from the app's folder:

```
.venv/bin/python tests/test_idiograph.py --changed
```

On Windows, `.venv\Scripts\python tests\test_idiograph.py --changed`. It compares the app's files with
main, committed, staged, in the working tree and new, and runs every area whose source names a changed
file or a top-level name the change touches: a function, class or constant whose lines changed in a
script or a Python file, a class, id or custom property of a rule that changed in a style sheet, an id
or class on a line that changed in a page. Every new area runs, and every area whose own file changed.
It prints each area it chose and why, one line each, and the names too common to choose by, a name more
than 20 areas carry, such as `app.js` or a class called `card`. `--area 158` runs one area alone,
`--area 157,158` or `--area 150-152` several, and `--area guidance` every area whose file name holds the
word, and with `--changed` it adds to that choice. The suite's own checks run after them every time,
and the last lines give the time and count the passed, the failed and the skipped.

The full suite runs in the coordinator's train, about four a day and one before the hand-over, by
`./verify` at the repository root, which sets `IDIOGRAPH_TRAIN=1` for its run. GitHub's run, where
`GITHUB_ACTIONS` is set, is a full one too, and `--train` asks for one. Anywhere else the file with no
`--area` or `--changed` runs nothing and says so in one line, and the unittest case is skipped with
the same line. A full run lists its 15 slowest areas at its end, and `--timings <file>` writes every
area's seconds and count of checks, slowest first.

## Writing a check

A check holds behaviour that matters: what is saved to a workbook or a file, what an import or an
export makes, what a key, a click or a drag does, what survives a restart. A change of words, colour,
spacing or layout gets review shots, never a check that pins a string, a colour or a pixel. Take
their boxes and crops with `packaging/shot_box.js` in the page and compose them with
`packaging/review_shot.js --boxes-from`, which refuses a shot that breaks the rules (`docs/internals.md`,
Review shots). Area 183 checks both tools.

## The files

Each area is a file of its own under `areas/`, named by its number and a short name,
`a158_guidance_sheet.py`, and holds one function, `test_guidance_sheet`, with any helper or constant
no other area uses. The number is the area's place in the order. From area 31 on it is the number
the area prints, and the first thirty print the numbers they were written with.

`areas/support.py` holds what more than one area uses: the paths, the check counter and its two
calls, `check` and `skip`, the demo fixture, the helpers and constants, and the suite's own checks.
An area imports from it what it needs, and nothing in it is copied into an area. A file of the app is
read by its path as it is now, `support.source("family/static/shell.js")` for its Path or
`support.text("apps/sift/static/sift.js")` for its text, several paths given to `text` joined in order, and
`support.static_folders()` is every static/ folder of the page. Until the sixth build (23 October 2026) an
alias table, `support.ALIASES`, took a file's path from before the family's folders to where it was, which
`--changed` read backwards. Area 253 counts the family's crossings against `tests/boundaries.json` (see
docs/internals.md, The family's folders) and holds each app's bundle to the family's and its own. The page as
the server serves it, the app's parts in their slots, is `support.page_text()`, Idiograph's by default and
`page_text(app="sift")` Sift's, since each app's page holds its own parts alone since the cutover, and
`support.every_page()` the family's page with every app's parts, for a check over all three apps' markup at
once. `support.as_app("sift")`, a context or a decorator, runs the suite's server and command line as Sift
or Trace in this process, as every Sift and Trace area does since Idiograph stopped answering for them.
A check that starts a real server child gives it `support.faulty_env(env)` (Python's faulthandler on) and a
`support.ChildWatch(kid, port)`: a wait that runs out calls its `ran_out(why)`, which sends the child SIGABRT
(on GitHub's runners alone, never on Windows) so every thread's traceback lands in its output, and a failed check's detail is
`watch.says(output)`, the seconds to the first answer or none, the child's exit code or that it still runs, and
