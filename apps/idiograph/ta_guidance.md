# Guidance rail

The eleven lines the app shows in the guidance panel on the Coding screen of a thematic analysis project,
written from Braun and Clarke's reflexive thematic analysis (2006, 2019, 2021, 2022). Each line starts
with `- ` and the server reads them in that order, so edit them here and they change in the app on the
next load. The plain paragraph under the heading is shown under the list in the panel, so it can be
reworded here too. Keep both short enough to take in at a glance.

Under each line, indented by two spaces, sit its two examples, one line starting `- Less this: ` and one
starting `- More this: `, each a short code, or what you do, on the demo's invented topic, sharing a home
with a dog. The panel opens them in two columns from the small arrow at the end of the line. The server
reads an indented line as the example of the line above it, never as a line of its own, and a line with no
examples shows no arrow.

## Holding the craft

1 to 3 are about the whole dataset, 4 to 8 about what a code is, 9 and 10 about codes changing as you
work, and 11 about you. This is reflexive thematic analysis as Braun and Clarke set it out. A codebook
approach, with its codes fixed before coding begins, is a different method.

- Read the whole dataset before you code, and read it again. Jot what strikes you in the notes.
  - Less this: Coding from the first line of the first interview
  - More this: Every interview read twice, with notes, before the first code
- Give every participant the same care. Code across the whole dataset, not only the passages that strike you.
  - Less this: The first three interviews coded closely, the rest skimmed
  - More this: The last interview coded as closely as the first
- Code what bears on your research question. A passage with nothing for your question needs no code.
  - Less this: Directions to the park
  - More this: No code, for a passage that gives directions to the park
- One idea per code. Beware a label that joins two ideas, or two conflicting ones.
  - Less this: Walks as freedom and as a chore
  - More this: Walks as freedom
- Code for meaning, not topic. A code says something about the data, not only what it is about.
  - Less this: Walks
  - More this: The walk as a reason to go out
- Code what is said, and look under it too. A latent code names an idea or assumption the words rest on.
  - Less this: Says the dog is good company
  - More this: Company that asks nothing in return
- Make each code stand alone. Its name should make sense without the extract beside it.
  - Less this: Relief when that stopped
  - More this: Relief when the night barking stopped
- An extract can carry more than one code. Give each idea in it a code of its own.
  - Less this: One code, Walks, on a passage about freedom and duty
  - More this: Two codes on it, Walks as freedom and The walk as a duty owed
- Reuse a code when an extract shares its idea. Rename or merge codes that turn out to say one thing.
  - Less this: Dog as family, Family dog, Rescue dog as family
  - More this: The dog as family, one code holding all three
- Code more than once. A second pass, in another order, shows what the first missed.
  - Less this: One pass, in interview order
  - More this: A second pass, from the last participant to the first
- Your perspective is the tool of the analysis, not a bias to remove. Note what you bring to a passage.
  - Less this: Coding as if you had no view of dogs
  - More this: A note that you have a dog of your own, and how it colours this passage

## Placeholders

The craft prompts the Add a code field shows one of, a fresh one on every passage. One per line, the app
picks at random, so add, cut or reword them freely. Keep them to a question that can be held in mind while
reading the passage.

These lines start with `* ` rather than `- ` on purpose, as in IPA's rail, so a server that sweeps the
whole file for `- ` never puts them in the rail.

* What is going on here, for your research question?
* What are they making of it, as they say it?
* What is said, and what is assumed under it?
* Does a code you have already hold this, or is it new?
* Why might they tell it this way?
* What do you bring to this passage?
* What would you call this, in a few words that stand alone?
